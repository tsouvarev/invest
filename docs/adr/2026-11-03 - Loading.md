# Пайплайн загрузки данных тикера

## Проблема

Данные тикера берутся из разных источников:

- база исторических данных
- Т-Банк (полное название)
- МосБиржа (ИНН)
- ЦБР (прогнозы)
- СмартЛаб (часто меняющиеся данные вроде котировок и купонов)

При этом если бумага не нашлась в Т-Банке,
то дальше в пайплайне ее можно не учитывать,
потому что финальная цель это покупка в Т-Инвестициях.

Также для выборки в ЦБР нужен ИНН с другой выборки.

## Варианты решения

- исключать из пайплайна подгрузки ISIN, которые не нашлись в Т-Банке (так было).
  Это рабочий вариант, но из-за того, что в поиске раз за разом
  находятся те тикеры, которые раньше были выкинуты,
  то приходится их каждый раз заново перезапрашивать
- пробрасывать данные с предыдущих шагов в следующий.
  Тут надо либо на каждом шаге пайплайна
  смотреть в историческую базу и в данные с предыдущих шагов,
  либо прозрачно подкладывать данные с прошлого шага в исторические данные
  (например, через ChainMap)
- не выкидывать пустые тикеры из пайплайна.
  С одной стороны это приводит к неоптимальной подгрузке в первый заход,
  но в следующий запуск поиска в исторической базе уже будут нужные тикеры
  с пустыми значениями, так что можно будет их игнорировать в пайплайне.

## Реализация

Решено было взять третий вариант как самый быстрый в реализации.

Потенциально хорошо выглядит второй, но надо продумать схема проксирования
(прототип с EAV-моделью поверх исторических данных зашел плохо).
